Lane 흐름과 상태

부르는 순서와 상태마다의 뜻입니다.

2026년 11월 26일 고침Branchlane 2.3

부르는 순서#

  1. lane_begin 뒤에는 돌려받은 워크트리 안에서만 작업합니다. 커밋은 마음대로 해도 됩니다. 미커밋 작업도 스냅샷으로 남습니다.
  2. 시작 전과 제안 전에 lane_status로 다른 에이전트가 건드리는 파일을 봅니다.
  3. lane_checkpoint는 언제든 부릅니다. 체크포인트 훅도 턴이 끝날 때마다 하나씩 남깁니다.
  4. 마지막 수정 뒤에 테스트, 빌드, 린트마다 lane_evidence를 부르고 받은 id를 챙깁니다.
  5. 요약과 그 id를 단 주장으로 lane_propose를 부릅니다.
  6. 나중에 lane_status로 검토 의견, 빠진 파일과 헝크, 메모를 읽습니다.

한 번 따라 해 보기#

아래 셸 함수는 도구를 부르고 안쪽 JSON만 꺼냅니다. 에이전트가 하는 일을 손으로 해 보거나 내 도구를 시험할 때 씁니다.

터미널
lane() {  # lane <도구> '<인자 JSON>'
  curl -s http://127.0.0.1:47120/mcp \
    -H "Authorization: Bearer $BRANCHLANE_TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",\"params\":{\"name\":\"$1\",\"arguments\":$2}}" \
    | jq '.result.content[0].text | fromjson? // .'
}

lane lane_begin '{"path":"/Users/me/src/app","intent":"Retry sync with backoff","agent":"me/manual"}'
cd /Users/me/src/app/.branchlane/lanes/a7f460dc      # 돌려받은 worktree
# … 고치고 커밋 …
swift test; lane lane_evidence "{\"path\":\"$PWD\",\"command\":\"swift test\",\"exit_code\":$?}"
lane lane_propose "{\"path\":\"$PWD\",\"summary\":\"Retries with backoff\",\"claims\":[{\"text\":\"Tests pass\",\"evidence\":[1]}]}"
lane_propose 결과
{
  "claims_without_current_evidence": [],
  "next": "The person reviews in Branchlane. Call lane_status later for feedback.",
  "status": "proposed"
}
