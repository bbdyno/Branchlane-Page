Defaults

.branchlane/policy.json in the main worktree tells Branchlane, and the agents it serves, what is allowed. Commit it so the whole team shares it. Settings > Agents can create it with these defaults:

{
  "forbid": ["force_push", "rewrite_history"],
  "protectedBranches": ["main", "master"],
  "protectedPaths": [],
  "requireApproval": ["push"],
  "requireEvidence": [],
  "sensitivePaths": []
}

How it decides

  • Actions are push, force_push, rewrite_history and integrate.
  • Decision order: a forbidden action is denied. On a protected branch, force-push and rewrite are denied and the rest go to the person. Otherwise actions in requireApproval go to the person and the rest are allowed.
  • requireEvidence lists command prefixes, such as swift test, that must have passed on exactly the proposed content before a lane can be accepted.
  • protectedPaths need an explicit yes for each file in review. sensitivePaths are shown first, on top of built-in ones such as migrations, auth code, CI workflows, lock files and .env files.
  • Patterns follow .gitignore rules. Keys are camelCase. A file that does not parse falls back to the defaults and the error shows in Settings.

Claude Code

Settings > Agents also turns the policy into Claude Code permissions.deny rules, so Claude Code itself refuses what the policy forbids.
