Order of calls

  1. lane_begin, then work only inside the returned worktree. Commit there as you like: Branchlane snapshots uncommitted work too.
  2. lane_status before you start and before you propose. It tells you which files other agents are touching.
  3. lane_checkpoint whenever you like. The checkpoint hook also saves one at the end of every turn.
  4. lane_evidence after your last edit, for each test, build or lint run. Keep the returned ids.
  5. lane_propose with a summary and claims that cite those ids.
  6. lane_status later, for review feedback, left-out files and hunks, and notes.

Walk through it once

This shell function calls a tool and unpacks the JSON inside. Use it to do by hand what an agent does, or to try your own tool.

lane() {  # lane <tool> '<arguments JSON>'
  curl -s http://127.0.0.1:47120/mcp \
    -H "Authorization: Bearer $BRANCHLANE_TOKEN" \
    -H "Content-Type: application/json" \
    -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",\"params\":{\"name\":\"$1\",\"arguments\":$2}}" \
    | jq '.result.content[0].text | fromjson? // .'
}
