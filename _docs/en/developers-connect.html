Add the server

Open Settings > Agents, turn on Let agents connect, and copy the line for your agent. It already holds your port and token. Branchlane never writes these files for you.

Run once in Terminal, then check that it connected:

claude mcp add --transport http branchlane \
  http://127.0.0.1:47120/mcp \
  --header "Authorization: Bearer <token>"

claude mcp list

Add to ~/.codex/config.toml:

[mcp_servers.branchlane]
url = "http://127.0.0.1:47120/mcp"
http_headers = { Authorization = "Bearer <token>" }

Use the Streamable HTTP transport with the endpoint http://127.0.0.1:47120/mcp and the header Authorization: Bearer <token>. The port can be changed in Settings.

{
  "mcpServers": {
    "branchlane": {
      "type": "http",
      "url": "http://127.0.0.1:47120/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}

Each client shapes its settings file a little differently. Only the address and the header have to match.

Try it by hand

Put the token in an environment variable and start a session:

export BRANCHLANE_TOKEN="the token from Settings"

curl -s http://127.0.0.1:47120/mcp \
  -H "Authorization: Bearer $BRANCHLANE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "jsonrpc": "2.0", "id": 1, "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {},
    "clientInfo": { "name": "my-tool", "version": "1.0" }
  }
}'
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": { "tools": { "listChanged": false } },
    "serverInfo": { "name": "branchlane", "version": "1" },
    "instructions": "Branchlane coordinates parallel agents in this repository. Start each task with lane_begin and work in the worktree it returns. …"
  }
}

Call a tool. path must be a repository you opened in Branchlane.

curl -s http://127.0.0.1:47120/mcp \
  -H "Authorization: Bearer $BRANCHLANE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
  "jsonrpc": "2.0", "id": 2, "method": "tools/call",
  "params": {
    "name": "lane_begin",
    "arguments": {
      "path": "/Users/me/src/app",
      "intent": "Retry sync with backoff when the server is busy",
      "agent": "my-tool/model-x",
      "scope": ["Sources/Sync/"]
    }
  }
}'

Read the result

Every tool returns its result as a JSON string inside a text item:

{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "{\n  \"branch\" : \"lane/retry-sync-with-backoff-a7f4\",\n  \"cloned\" : [],\n  \"lane_id\" : \"a7f460dc\", ... }" }],
    "isError": false
  }
}

Unpacked with jq, it looks like this:

curl -s … | jq '.result.content[0].text | fromjson'
{
  "branch": "lane/retry-sync-with-backoff-a7f4",
  "cloned": [],
  "lane_id": "a7f460dc",
  "next": "Work only inside `worktree`. Commit there as you like; Branchlane snapshots uncommitted work too.",
  "target": "refs/heads/main",
  "worktree": "/Users/me/src/app/.branchlane/lanes/a7f460dc"
}

When a tool fails, HTTP is still 200, isError is true, and the text says why.
