Developers/Reference

Tools

Every MCP tool, its arguments and what it returns.

Updated November 26, 2026Branchlane 2.3

Results below show the JSON inside result.content[0].text, unpacked. Keys arrive in alphabetical order and the indentation may differ.

Common arguments#

Every tool takes these.

ArgumentTypeDescription
pathrequiredstringYour working directory: the repository, or the lane's worktree.
lane_idstringCan be left out when path is inside the lane's worktree.

lane_begin#

Starts a lane: a branch lane/<slug>-<id> and a worktree under .branchlane/lanes/<id>. Work only in that worktree afterwards. Returns lane_id, worktree, branch and target.

ArgumentTypeDescription
intentrequiredstringWhat the person asked for, in one or two sentences.
agentstringYour tool and model, such as claude-code/claude-opus-5-5.
scopestring[]Paths you expect to change. A hint for collision warnings.
targetstringBranch the work should land on. The repository's main branch if left out.
clonestring[]Ignored folders to copy from the main worktree, such as node_modules or .build.
Result
{
  "branch": "lane/retry-sync-with-backoff-a7f4",
  "cloned": ["node_modules"],
  "lane_id": "a7f460dc",
  "next": "Work only inside `worktree`. Commit there as you like; Branchlane snapshots uncommitted work too.",
  "target": "refs/heads/main",
  "worktree": "/Users/me/src/app/.branchlane/lanes/a7f460dc"
}

lane_statusRead-only#

Where the lane stands: its status, whether recorded evidence still matches the code, review feedback, files and hunks the person left out, and collisions with other worktrees or the target, with line ranges and which side should go first.

Result
{
  "branch": "lane/retry-sync-with-backoff-a7f4",
  "collisions": [{
    "advice": "Your lane should land first. Keep your changes on these lines as they are.",
    "conflict_lines": [{ "path": "Sources/Sync/SyncEngine.swift", "theirs": ["41"], "yours": ["40-60"] }],
    "conflicts": ["Sources/Sync/SyncEngine.swift"],
    "integrate_first": "you",
    "same_files": ["Sources/Sync/SyncEngine.swift"],
    "with": "/Users/me/src/app/.branchlane/lanes/c19e02b7"
  }],
  "evidence": [{ "command": "swift test", "current": true, "exit_code": 0, "id": 1 }],
  "intent": "Retry sync with backoff when the server is busy",
  "lane_id": "a7f460dc",
  "status": "running",
  "target": "refs/heads/main",
  "worktree": "/Users/me/src/app/.branchlane/lanes/a7f460dc"
}

After a review it can also carry review_feedback (why it came back), rejected_files (files left out, with reasons), left_out_hunks and note. When the content changes after a run, current turns false and changed_since lists the files.

lane_checkpoint#

Snapshots the worktree, uncommitted changes included, without staging or committing.

ArgumentTypeDescription
notestringA word about the snapshot.
Result
{ "checkpoint": "5f0c8e1…", "tree": "b41d9a2…" }

lane_evidence#

Records that a command ran on the current content and how it ended. It is valid only while the content stays exactly the same, so call it after your last edit. Returns evidence_id.

ArgumentTypeDescription
commandrequiredstringThe command that ran, such as swift test.
exit_coderequiredintegerHow it ended. 0 is a pass.
outputstringThe command's output. Only the end is kept, with secrets masked.
Result
{
  "evidence_id": 1,
  "note": "Valid only while the content stays exactly as it is now. Cite this id in lane_propose claims.",
  "tree": "b41d9a2…"
}

lane_propose#

Asks the person to review the lane as it is now. Claims without current evidence are flagged.

ArgumentTypeDescription
summaryrequiredstringWhat changed and why, for the reviewer.
claimsobject[]Statements with the evidence ids that back them: { text, evidence[] }.

Example#

JSON
{"name": "lane_propose", "arguments": {
  "path": "/Users/me/src/app/.branchlane/lanes/a7f460dc",
  "summary": "Pushes are retried with exponential backoff and jitter. Six attempts at most.",
  "claims": [
    { "text": "A busy server is tried again, up to six times", "evidence": [1] },
    { "text": "The library file format is unchanged" }
  ]
}}
Result
{
  "claims_without_current_evidence": ["The library file format is unchanged"],
  "next": "The person reviews in Branchlane. Call lane_status later for feedback.",
  "status": "proposed"
}

lane_request#

Asks to push, force-push or rewrite history. The policy decides, and some requests wait up to two minutes for the person. An approved push runs with the person's credentials.

ArgumentTypeDescription
actionrequiredenumpush, force_push or rewrite_history.
reasonstringWhy, shown to the person.

One of three answers comes back, depending on the policy and the person. Denied and declined answers have isError set to true.

JSON
{ "decision": "approved", "done": true, "output": "To github.com:me/app.git\n   9b26e1e..4c1d2e0  lane/retry-sync-with-backoff-a7f4 -> lane/retry-sync-with-backoff-a7f4" }

Rewriting history happens inside the lane branch, by the agent itself. That answer has "done": false and a note saying it may go ahead.

JSON
{ "decision": "denied", "reason": "The repository's policy forbids force_push." }
JSON
{ "decision": "declined", "reason": "The person did not approve it." }
